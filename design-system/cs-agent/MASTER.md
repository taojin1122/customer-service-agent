# CS Agent 设计系统

> 适用范围：平台运营端（`/platform`）、租户管理端（`/tenant`）、坐席工作台（`/console`）、用户侧客服窗（`/widget`）。
> 代码落点：`frontend/src/styles/tokens.css`。本文与它冲突时，以本文为准。

---

## 0. 定位

**B2B 智能客服 SaaS：三个后台端 + 一个嵌入式窗口。**

设计取向由使用场景决定，而不是由"看起来现代"决定：

| 端 | 谁在用 | 单次时长 | 对设计的真实要求 |
|---|---|---|---|
| 平台运营端 | 我们自己的运营 | 短，按需 | 数据全、能快速定位问题租户 |
| 租户管理端 | 客户管理员 | 短，偶尔 | 表单清楚、保存有明确反馈 |
| 坐席工作台 | 一线客服 | **连续 8 小时** | 低视觉疲劳、键盘可操作、信息层次稳定 |
| 用户侧客服窗 | 终端消费者 | 几十秒 | 体积小、加载快、不干扰宿主页面 |

一句话：**浅色瑞士风 + 高信息密度 + 颜色只用于传达状态。**

## 1. 与检索推荐的偏离（先看这节）

`ui-ux-pro-max` 的 `--design-system` 两次检索都给出了推荐，其中若干条经核对不适合本产品，**刻意不采纳**。记录在此，避免后续维护者以为是遗漏而"修正"回去。

| 推荐项 | 是否采纳 | 原因 |
|---|---|---|
| 风格：Glassmorphism | ❌ 拒绝（**仅限后台界面**） | 毛玻璃依赖背景模糊。工作台是密集表格与消息流，模糊会持续削弱文字边缘对比度；且 `backdrop-filter` 在集显笔记本上掉帧，坐席全天使用等于全天卡顿。**登录页不受此限**，见 §2.4 |
| 配色：深色背景 `#0F172A` 默认 | ❌ 拒绝 | 该次推荐的 anti-pattern 里自己写了 "Dark mode by default"。坐席连续 8 小时面对深色底 + 深色表格，行区分度比浅色差；浅色更适合白天办公环境。深色保留为可选主题，不做默认 |
| 版式：Hero + Features + CTA | ❌ 拒绝 | 这是营销落地页结构。本项目是后台应用，无 Hero、无 CTA |
| 版式：Real-Time / Operations Landing | ❌ 拒绝 | 同上，仍是落地页模式，只是换了名字 |
| 字体：Fira Code 作标题 | ❌ 拒绝 | 等宽字体无中文字形，中文会 fallback 到系统字体，导致中英混排节奏散乱；且等宽字体的字面宽度会把中文标题撑得很开 |
| 风格：Minimalism & Swiss Style | ✅ 采纳 | 栅格、留白、高对比，与"长期使用、信息密集"完全吻合 |
| 配色：SaaS General（`#2563EB` + `#F8FAFC`） | ✅ 采纳 | 蓝灰是 SaaS 后台的信任色基线，且明度差足够做层级 |
| 密度：8/10 | ✅ 采纳 | 后台需要一屏容纳更多行，密度高不等于拥挤，靠间距节奏而非留白堆叠 |

**补充判断**：检索库偏英文产品，字体推荐没有中文字形。中文必须显式声明 fallback 字体栈，否则 Windows 上会落到宋体，字号观感与设计稿差一档。

## 2. 色彩

**色彩纪律：界面主体只用中性色，彩色只表示状态。**

后台最怕的是"到处有颜色"——颜色一多，红色告警就不显眼了。因此：

- 中性色承担 90% 面积（背景、边框、文字、卡片）
- 品牌蓝只用于**主操作**（每屏最多一个）
- 橙色只用于**需要抓注意力的一次性动作**：转人工、结束会话、升级工单
- 语义色只用于状态，且**不能只靠颜色传达**（必须同时有文字或图标）

### 2.1 浅色主题（默认）

| 角色 | 值 | Token | 用途 |
|---|---|---|---|
| 品牌主色 | `#2563EB` | `--color-primary` | 主按钮、当前导航项、链接 |
| 主色悬停 | `#1D4ED8` | `--color-primary-hover` | |
| 主色弱底 | `#EFF6FF` | `--color-primary-soft` | 选中行底、标签底 |
| 强调色 | `#EA580C` | `--color-accent` | 转人工、结束会话、升级 |
| 强调弱底 | `#FFF7ED` | `--color-accent-soft` | |
| 页面背景 | `#F8FAFC` | `--color-bg` | |
| 卡片背景 | `#FFFFFF` | `--color-surface` | |
| 次级面 | `#1E293B` | `--color-sidebar` | 侧边栏（唯一允许的深色块） |
| 主文字 | `#0F172A` | `--color-text` | 正文、标题 |
| 次文字 | `#475569` | `--color-text-secondary` | 说明、时间戳 |
| 弱文字 | `#94A3B8` | `--color-text-tertiary` | 占位符、禁用 |
| 边框 | `#E2E8F0` | `--color-border` | 分隔线、卡片描边 |
| 强边框 | `#CBD5E1` | `--color-border-strong` | 输入框、可聚焦元素 |
| 成功 | `#16A34A` | `--color-success` | 在线、已解决 |
| 警告 | `#F59E0B` | `--color-warning` | 排队超时、配额接近上限 |
| 危险 | `#DC2626` | `--color-danger` | 停用、删除、错误 |

### 2.2 强调色只有三处

这是硬约束，不是建议：

1. **转人工**（工作台头部、客服窗底部）
2. **结束/关闭会话**
3. **升级为工单**

除此之外任何地方用橙色，都会被判定为设计错误。理由：橙色一旦泛用，上面三个真正需要用户注意的动作就淹没在界面里了。

### 2.3 深色主题

预留但不默认。`tokens.css` 里以 `[data-theme="dark"]` 覆盖同名变量，切换时**只覆盖变量，不改组件样式**。禁止在组件里写 `if (dark) ...` 的分支。

### 2.4 品牌页例外：登录页

**登录页是唯一允许使用装饰渐变、彩色柔光、网格纹理与入场动画的页面。**

理由不是"登录页更好看"，而是两者的评价标准不同：

| | 后台界面（工作台/管理端） | 登录页 |
|---|---|---|
| 被看多久 | 连续数小时 | 3~10 秒 |
| 首要目标 | 长时间阅读不疲劳、信息密度 | 第一印象、品牌质感 |
| 装饰的代价 | 削弱对比度、拖慢渲染、占用注意力 | 几乎为零 |

因此登录页允许：彩色柔光背景、网格纹理、渐变文字、渐变按钮、入场位移。

**不使用玻璃拟态**：那需要深色或不均匀背景作为前提。登录页是明亮底色，模糊之后仍是浅色，只会让卡片显脏，收益为零。质感的来源改为「双层阴影 + 极淡边框 + 渐变按钮」。

仍然必须遵守：文字对比度 ≥ 4.5:1、可见焦点、`prefers-reduced-motion` 下停止循环动画、错误提示带 `role="alert"`。

**边界判定规则**：一个页面若「用户会在此停留并反复阅读内容」，按后台标准；若「只做进入/确认，随即跳走」，可按品牌页标准。按此规则，登录页、注册页、错误页属于品牌页；概览、列表、详情、对话一律按后台标准。

登录页的配色是**独立于主题的固定视觉**，不跟随 `[data-theme]` 切换——它用的是组件内局部变量（`--lp-*`），不出现在 `tokens.css` 里，避免与后台主题互相污染。

### 2.5 活力色的使用边界

`tokens.css` 里有三个装饰性 token：`--color-violet`、`--color-cyan`、`--gradient-brand`。

| | 允许 | 禁止 |
|---|---|---|
| 品牌页 | 柔光、渐变文字、渐变按钮 | — |
| 工作台 | 图表色板、空状态插画、统计数字强调 | 正文文字、表格行、表单控件边框 |
| 通用 | — | 替代语义色（成功/警告/危险必须用语义色） |

**为什么要写这条边界**：装饰色一旦出现在信息载体上（比如给"处理中"加个紫色边框），用户就会开始把紫色理解为某种状态含义。语义体系一旦被污染，后面每加一个颜色都要解释"这个紫和那个紫不一样"，最终没人能说清。

**判定方法**：问自己"这个颜色是否在传达状态"。传达状态 → 用语义色；纯装饰 → 用活力色。

## 3. 字体

### 3.1 字体栈

```css
--font-sans: "Plus Jakarta Sans", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif;
--font-number: "Plus Jakarta Sans", ui-monospace, "SF Mono", Consolas, monospace;
```

**为什么中西文字体分开声明**：Plus Jakarta Sans 没有中文字形，中文必然 fallback。若不显式把 `PingFang SC` / `Microsoft YaHei` 写在中间，浏览器会跳到 `system-ui` 之外的默认字体（Windows 上是宋体），中文会变成衬线，与西文的无衬线风格冲突。

### 3.2 字号阶梯（密度 8/10）

| 用途 | 字号 / 行高 | Token |
|---|---|---|
| 页面标题 | 20px / 28px | `--text-xl` |
| 区块标题 | 16px / 24px | `--text-lg` |
| 正文 | 14px / 22px | `--text-base` |
| 辅助说明 | 13px / 20px | `--text-sm` |
| 时间戳 / 标签 | 12px / 18px | `--text-xs` |

**为什么正文是 14 而不是 16**：后台一屏要放表格与消息流，16px 会让行高撑到 26px，同样高度少显示两行。这是后台与消费级产品的本质差异，不要用移动端的字号直觉套用。

### 3.3 数字必须等宽

消息时间、会话计数、Token 用量、席位使用量等数字加 `font-variant-numeric: tabular-nums`。

不这样做时，用户每收到一条消息，右侧时间列会因为数字宽度不同而微微抖动——长时间盯着非常烦躁，且难以察觉来源。

## 4. 间距、圆角、阴影

| Token | 值 | 典型用途 |
|---|---|---|
| `--space-1` | 4px | 图标与文字间距 |
| `--space-2` | 8px | 组件内边距（紧凑） |
| `--space-3` | 12px | 组件内边距（默认） |
| `--space-4` | 16px | 卡片内边距 |
| `--space-6` | 24px | 区块间距 |
| `--space-8` | 32px | 页面分节 |

| Token | 值 | 用途 |
|---|---|---|
| `--radius-sm` | 6px | 输入框、标签 |
| `--radius-md` | 8px | 卡片、按钮 |
| `--radius-lg` | 12px | 弹窗、客服窗 |
| `--radius-full` | 999px | 头像、状态点 |

阴影只允许两级，且极轻：

```css
--shadow-sm: 0 1px 2px rgba(15, 23, 42, 0.04);
--shadow-md: 0 4px 12px rgba(15, 23, 42, 0.08);
```

**为什么不用更强的阴影**：后台页面是并列的信息块，阴影过重会让每张卡片都像浮起，视觉噪声叠加后反而分不清层级。层级靠**背景色差 + 1px 边框**表达，阴影只用于真正浮起的元素（下拉、弹窗、客服窗）。

## 5. 三端差异

同一套 token，布局与密度不同。

| 维度 | 平台运营端 | 租户管理端 | 坐席工作台 | 客服窗 |
|---|---|---|---|---|
| 路由 | `/platform/*` | `/tenant/*` | `/console/*` | `/widget/*` |
| 侧边栏 | 深色 240px + 顶部橙色环境条 | 深色 240px | 无侧栏，三栏布局 | 无 |
| 信息密度 | 最高（表格为主） | 中（表单为主） | 高（消息流） | 低 |
| 主色用法 | 仅主操作 | 仅主操作 | 仅主操作 | 仅发送按钮 |
| 组件库 | Element Plus | Element Plus | Element Plus | **不用**，纯 CSS |
| 深色主题 | 支持 | 支持 | 支持 | 跟随宿主或系统 |

**平台端为什么要一条橙色细条**：内部运营和租户管理员用的是同一个 SPA，视觉几乎一致。运营在自己的系统里做"停用某租户"这类不可逆操作时，如果和客户的管理端长得一样，极易操作错环境。一条 4px 的橙色条 + 顶部标记「平台运营」是成本最低的防错手段。

**客服窗为什么不用 Element Plus**：它要嵌进租户自己的网站，带 300KB 组件库会拖慢宿主页面加载。它只需要按钮、输入框、滚动区域，手写 200 行 CSS 就够。

## 6. 组件规范

### 6.1 消息气泡

| 属性 | 用户消息 | 机器人消息 |
|---|---|---|
| 对齐 | 右 | 左 |
| 背景 | `--color-primary` | `--color-surface` + 1px 边框 |
| 文字 | 白 | `--color-text` |
| 最大宽度 | 72% | 72% |
| 圆角 | `12px 12px 2px 12px` | `12px 12px 12px 2px` |
| 内边距 | `10px 14px` | `10px 14px` |

**为什么最大宽度 72% 而不是 80%**：超过 75% 时，左右两侧的留白消失，用户与机器人的消息在视觉上会连成一片，分不清谁说的。72% 能保住一条清晰的对话中轴。

**圆角切角**：贴近说话者一侧的角收小（2px），是唯一不用文字就能表达方向的方式。

### 6.2 流式状态

机器人正在生成时：

- 气泡内显示 3 个 4px 圆点，依次透明变化（周期 1.2s）
- **不用"正在输入…"文字**：文字会在停止时突然被替换成整段回答，造成内容跳动
- 停止后直接在第一帧替换为文字，气泡宽度用 `min-width` 预留，避免塌缩

**为什么强调这一点**：消息流里任何宽度跳变都会把下方所有内容上推或下拉。用户正在读历史消息时被推走，是最影响体验的一类问题。

### 6.3 空状态

所有列表（会话、知识库文档、租户、坐席）必须有三样：

1. 一句说明"这里会有什么"
2. 一个**可直接执行**的动作按钮
3. 不含装饰性插画

示例：「还没有上传文档。上传后，机器人会基于文档内容回答用户问题。」+「上传文档」按钮。

**不要**出现"暂无数据"四个字。它没有告诉用户该做什么，用户只能去问人。

### 6.4 表格

- 行高 48px（密度 8/10）
- 表头背景 `--color-bg`，文字 `--color-text-secondary`，12px 字重 500
- 数值列右对齐 + `tabular-nums`
- 状态列用「圆点 + 文字」，不只用颜色
- 空状态占据表体区域，不与表头重叠

### 6.5 表单

- 标签在输入框上方（不用 placeholder 当标签）
- 错误提示在输入框下方 4px，红色 13px
- 提交时按钮进入 loading，**禁止重复提交**
- 成功后给出明确反馈（Toast + 数据刷新），不能只在控制台静默成功

### 6.6 危险操作

停用租户、删除坐席、清空知识库必须二次确认，确认弹窗里：

- 标题写清对象（「停用租户 阳城国际？」）
- 正文写清后果（「该租户所有账号将立即无法登录，已签发的令牌在过期前仍有效」）
- 确认按钮用危险色，且**文案是动词**（「停用」），不是「确定」

## 7. 无障碍要求

来自 UX 检索的硬性项，不可省略：

| 项 | 要求 |
|---|---|
| 正文对比度 | ≥ 4.5:1（浅色、深色各自测，不能套用） |
| 非文字对比度 | 图标与控件边界 ≥ 3:1 |
| 焦点可见 | 所有可交互元素有 `:focus-visible` 描边，不允许 `outline: none` 无替代 |
| 表单错误 | `role="alert"` 或 `aria-live`，不能只变红边框 |
| 状态不只靠颜色 | 在线/离线、成功/失败都要有文字 |
| 减弱动效 | `prefers-reduced-motion: reduce` 时关闭所有位移与循环动画，只保留透明度变化 |
| 图标 | 用 SVG 图标，不用 emoji；纯装饰图标 `aria-hidden="true"` |
| 流式内容 | 滚动跟随可关闭（用户上滑阅读历史时不能被拉回底部） |

## 8. 禁止清单

| 禁止 | 原因 |
|---|---|
| 用 emoji 当图标 | 跨平台字形不一致，无法跟随主题色 |
| 硬编码十六进制颜色 | 深色主题会失效，必须走 CSS 变量 |
| `outline: none` | 键盘用户会完全失去位置感 |
| 装饰性渐变与玻璃拟态 | 削弱文字对比，且与"高密度表格"冲突 |
| 超过两级的阴影 | 层级噪声 |
| 橙色使用在 §2.2 三处之外 | 稀释真正的警示 |
| 用 placeholder 代替标签 | 输入后标签消失，用户忘记在填什么 |
| 骨架屏与真实内容高度不一致 | 加载完成瞬间页面跳动 |
